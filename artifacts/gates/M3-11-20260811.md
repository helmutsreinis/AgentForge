## Security and portability review

The connect callback receives the HTTP stack's exact destination, rejects any host/port mismatch,
resolves the configured host once, validates the complete normalized answer, and connects directly
to one approved address. The HTTP stack therefore cannot silently resolve a different IP after the
policy decision. TLS Server Name Indication and certificate validation continue to use the original
configured hostname.

Loopback accepts only IPv4/IPv6 loopback. PrivateNetwork accepts only RFC1918 or unique-local IPv6.
Cloud rejects every non-global or reserved shape covered by the fixture. Mixed answers always fail;
the connector never cherry-picks apparently safe addresses from a suspicious response. Resolution
is capped at 64 results and occurs again only when a new connection is required; pooled connections
expire within five minutes.

The implementation uses portable .NET DNS/socket APIs and identical Windows/Linux policy tests.
It does not weaken TLS, enable proxies, follow redirects, or expose resolved addresses to ordinary
audit. Explicit `InProcess` HTTP location is invalid.

- OpenAI, Anthropic, DeepSeek, generic-compatible, and vLLM named profile adapters remain the final
  Milestone 3 provider slice.
- Address classification is not firewall/container isolation; the live container gate remains open
  because Docker is unavailable locally.
- The production provider catalog and governed loop executor remain empty; public invocation is
  still disabled.

## Rollback

Remove the policy/connect callback, explicit destination option, tests, ADR 0029, documentation,
and this report only while public invocation and hosted production catalog composition remain
disabled. Do not replace it with profile-time DNS validation or a default handler. No schema or
operator-data rollback is required.
