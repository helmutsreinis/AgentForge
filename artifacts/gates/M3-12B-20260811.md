## Security and portability review

Only an exact Anthropic HTTPS/cloud profile can construct the hosted adapter. DNS/socket policy is
enforced before transport. Prepared context is serialized instead of caller-owned mutable input.
The API key exists only as a bounded header around `SendAsync`, after which both the header and
clearable lease are removed. Remote error messages are never echoed. Completion requires ordered
start, closed content blocks, terminal usage/finish evidence, and `message_stop`.

The adapter uses BCL HTTP/JSON primitives and deterministic fixtures, so its non-live behavior is
identical on Windows and Linux. Live Anthropic credentials remain unavailable and do not block the
contract/fake/failure gate.

## Remaining findings

- Media and structured-output translation are explicitly unsupported by this adapter.
- Production composition intentionally exposes no provider until an administrator-configured
  runtime catalog and authenticated invocation surface pass later gates.

Remove the Anthropic adapter/options/writer/state translator, its exact profile-validator entry,
