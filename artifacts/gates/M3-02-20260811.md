## Security and portability review

Public construction owns a `SocketsHttpHandler` with redirects, cookies, proxies, and
automatic decompression disabled. It accepts no caller HTTP client, header dictionary,
credential reference, or media resolver. HTTPS is required unless the composition visibly
opts into plaintext HTTP. Endpoint user info, query, fragment, unexpected successful
response URI, and available image/audio/document capability evidence fail closed. The
unit-test-only fake handler is assembly-scoped and cannot become production composition.

Outbound JSON comes only from a normalized snapshot and is byte-bounded. Prior tool-result
error state is preserved in a JSON envelope. Response media type, declared and observed
length, SSE lines/events, UTF-8, JSON depth/unique keys, tool identity/arguments, structured
output, usage, finish reason, output tokens, event count, and wall time are checked. Remote
error bodies and exception messages are not copied inward. A malformed, truncated,
over-budget, redirected, reasoning-channel, or substituted-tool stream terminates with a
typed error and no later completion.

Windows and Linux use the same BCL HTTP/JSON implementation. Plaintext HTTP is not inferred
from private addressing; the operator must set the live endpoint and the option is derived
explicitly for that test invocation. The checked-in live test has no endpoint, model,
credential, or network activity when its two environment variables are absent.

## Remaining findings

- Model-context redaction is not connected. Only the fixed non-secret live-test prompt may
  cross this adapter until a typed context-preparation service passes its security gate.
- The adapter is credential-free. Hosted provider secrets require exact profile/reference
  binding, one-invocation materialization/disposal, safe header construction, and redaction.
- Destination policy, DNS/IP revalidation, locality routing, provider health/failover, audit,
  durable snapshots, retry budgets, and cumulative usage/cost remain later Milestone 3 gates.
- Media capability is deliberately refused. An artifact resolver and approved capable route
  must exist before image/audio/document bytes can cross a provider boundary.
- No public endpoint or CLI command exists, and production DI retains an empty provider
  catalog; setup profile acceptance still cannot make a model callable.

## Rollback

Remove the five compatible-adapter source files, its test-only `AssemblyInfo`, deterministic
and live tests, the IntegrationTests project reference, ADR 0019, traceability/threat/
architecture/runbook/project-state updates, and this gate report. There is no database
migration, package change, durable provider state, secret, or external artifact to reverse.
Keep production DI empty; do not replace this adapter with a direct `HttpClient` call.
