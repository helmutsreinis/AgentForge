## Security and portability review

The catalog snapshots definitions before publication and keys them by exact normalized ID
and version. Complete SemVer 2 parsing and comparison is implemented without numeric
conversion, so large valid version components cannot overflow. Provenance source and trust
must form an allowed pair and include exact source version plus lowercase SHA-256 evidence.
Side effects establish a minimum risk class; unknown flag bits fail closed.

A targeted descriptor must map authorization to a required text parameter. Every parameter
is typed, bounded, unique, and bound exactly once to a positional, named-value, or boolean-
switch argument form compatible with its type. Executable paths must be fully qualified,
but admission deliberately does not test existence or invoke the candidate. Environment
names use case-insensitive uniqueness on every platform so a descriptor admitted on Linux
cannot become ambiguous on Windows.

Search validates bounded query/filter/result inputs and yields summaries with descriptor
hashes but no execution template. Description requires exact ID/version and never silently
upgrades. Descriptions are still data, not authority. No public caller can invoke a
descriptor in this slice.

## Remaining findings

- Catalog provenance records signature-verified sources but plugin signature verification
  and loading remain Milestone 10 gates.
- A catalog hash describes admitted configuration, not the current bytes at the executable
  path. Safe availability/version/help probes and executable evidence must run later through
  the policy-bound restricted executor.
- The next invocation service must accept parameter values only; reconstruct capability,
  risk, target, executable, argument map, bounds, and isolation from the exact descriptor;
  bind its hash into authorization; atomically consume an exact approval and append audit/
  outbox start evidence before process launch.
- Restricted host remains unsuitable for hostile or high-risk binaries. Docker is absent;
  the container/namespace adapter and live image gate remain open without fallback.

## Rollback

This slice changes no durable schema and enables no invocation surface. Stop the host and
remove the tool-catalog registration, contracts, records, tests, and documentation together.
Existing inventory, approval, audit, installation, artifact, and secret data need no
transformation. Leave invocation disabled after rollback; never replace the catalog with
PATH lookup or caller-supplied executable metadata.
