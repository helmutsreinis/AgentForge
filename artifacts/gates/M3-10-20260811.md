## Security and portability review

The loop state machine accepts no model prose, raw tool output, endpoint, credential, executable,
or argument. Every record contains normalized hashes and bounded counters. The canonical hash binds
length-prefixed authority, phase/state, budgets, consumption, progress, correlation, timestamps,
and prior hash; any field edit invalidates the snapshot. Sequence and installation-scoped
idempotency indexes make concurrent initial writes fail deterministically.

Only Persist accepts progress evidence or advances a turn. Completion cannot skip Reflect/Persist.
Structured rejection repeats the current phase within a maximum of 32 repairs. Repeated progress
has its own bound. Checked token/tool totals and saturating elapsed seconds produce typed terminal
budget evidence rather than overflow. Cancellation is persisted using a non-canceled cleanup path.

Resume requires an exact loop ID, installation/agent version, budget, initial-state hash, actor,
correlation, causation, and idempotency key. Terminal replay is read-only. Each snapshot and its
redacted audit event share one transaction. The implementation and schema are OS-neutral; identical
Windows and Linux tests prove chain construction and recovery.
