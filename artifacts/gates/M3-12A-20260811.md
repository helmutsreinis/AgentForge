## Security and portability review

Provider type is an exact normalized identity and cannot silently fall through to a generic
adapter. Validation requires the configured secret-store name and clears every materialized buffer.
Control characters, empty/oversized credentials, URI credentials/query/fragment, unknown types,
cloud plaintext, and mismatched stores fail before profile persistence.

Setup capability evidence is intentionally weaker than a probe: text and streaming are configured,
while tools and images remain false. Endpoint validation is repeated at invocation by the exact
socket destination policy. The validation and adapter paths are portable managed code and pass
identically on Windows and Linux.
