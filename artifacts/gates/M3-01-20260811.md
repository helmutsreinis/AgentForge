## Security and portability review

No provider or SDK chooses policy fields. Requests carry exact model/profile context,
correlation, typed content, artifact references, tool schemas, response format, sampling,
and hard limits. The adapter snapshots the graph and computes provenance before returning
the first event. Media bytes never enter filenames or inline transport; filename checks
reject both slash forms consistently on Windows and Linux.

JSON parser differentials are constrained by fixed size/depth, strict parsing, recursive
duplicate-property rejection, and normalized completion values. Tool call history and
tool results have explicit content records, so a follow-up request does not need vendor
types. Evidence source and availability are separate; all relevant records must be current
and available, and the deterministic provider cannot turn unknown/expired evidence into a
capability.

The deterministic adapter is a trusted fixture, not an external-response sanitizer. Its
scripts are immutable after admission, bounded, and validated against capabilities and
terminal ordering. The production catalog is empty, so completing setup with a provider
profile does not make the runtime callable. No external trust boundary is crossed in this
slice.

## Remaining findings

- Model-context secret redaction and invocation-scoped credential materialization must pass
  before an external adapter can send a request.
- Routing must intersect data locality, policy-approved and observed capability, health,
  context/tool support, cost, and latency. This slice does not select or fail over providers.
- Provider HTTP/SSE error translation, streaming truncation, retry semantics, usage
  reconciliation, and structured-output repair remain adapter gates.
- Capability evidence and requests are in-memory snapshots; durable run snapshots, audit,
  budgets across retries, and cost ledgers remain later Milestone 3 slices.
- The local `qwen3.6` endpoint has not been called by this slice; its credential-free dry
  run belongs to the next OpenAI-compatible adapter gate.

## Rollback

Remove `AgentForge.Models`, its Domain/Abstractions records, Host registration/reference,
solution and test references, generated lock-file edges, tests, ADR, and documentation as
one unit. The slice has no database migration or external state. Leave production with no
model-provider catalog and no invocation route; do not substitute the older setup
capability booleans as a runtime adapter contract.
