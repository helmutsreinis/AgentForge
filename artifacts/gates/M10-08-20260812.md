# Gate M10-08 — Digest-pinned container execution

Status: **Pass**

## Scope

- Close the production container-sandbox implementation gap for AF-SEC-004.
- Preserve explicit typed unavailability on hosts without an equipped Docker runtime.

## Evidence

- `DockerContainerSandboxTests` passes hardened argument construction, exact image/runtime/executable identity, hostile-argument non-interpretation, read-only workspace mounting, empty environment, typed unavailability, denial, and unconditional cleanup.
- `PluginIsolationTests`, `CodingPatchAndVerificationTests`, and the complete restricted-host hostile process matrix pass after sandbox selection was composed.
- `DockerSandboxLiveTests` is a named equipped gate; release CI builds `packaging/container/Dockerfile.sandbox`, pins the local SHA-256 image ID, and runs the real adapter.
- Release asset tests require the non-root sandbox image and live release workflow step.

## Security and portability

- Container requests cannot fall back to restricted host. Only denied networking is supported.
- Root filesystem, capabilities, privilege escalation, workspace mode, temporary storage, CPU, memory, and PIDs are explicitly constrained.
- Windows Docker Desktop and native Linux Docker use the same argument-array adapter. Absence is a typed capability result.

## Rollback

Clear Docker sandbox configuration to make container execution unavailable. Remove the
selector/adapter and image only together; leave high-risk plugins and verifiers closed.
