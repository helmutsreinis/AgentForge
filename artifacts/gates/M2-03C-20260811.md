## Security and portability review

The request surface contains no caller-supplied capability/risk, target kind, executable,
argument template, environment, limits, network policy, or sandbox selection. Parameter
collections are snapshotted before asynchronous work. Exact schema validation and
descriptor-owned rendering occur before policy evaluation. Authorization canonicalizes
parameters, target, and workspace and includes descriptor hash in the request hash.

The first EF `SaveChanges` transaction updates approval concurrency version, inserts the
unique installation-scoped invocation key, and appends chained audit. A conflict returns
before `ISandbox`. Terminal writes and completion audit use another transaction. Raw output
is bounded by the sandbox and returned only to the immediate caller; persistence retains
hashes/lengths. Cancellation cleanup attempts a terminal canceled record without using the
already-canceled caller token.

The deterministic sandbox fixture claims Container plus loopback isolation and verifies the
application boundary on both platforms without requiring Docker. Production composition is
safer: the catalog is empty and restricted host rejects denied/loopback network controls,
so no callable descriptor can degrade to host networking. Docker remains absent locally and
the live container gate remains open.

## Remaining findings

- Database authorization cannot be atomic with OS process creation. A crash after the first
  commit produces `Authorized`; automatic retry is forbidden and requires operator review.
- A policy change can race after the final re-read and before process start. Normal versioned
  edits are rechecked, but later durable orchestration should introduce leases/pins checked
  by policy mutation paths.
- Executable bytes may change between descriptor admission, sandbox path checks, and process
  open. Safe probes need executable evidence; high-risk tools require stronger container/
  namespace isolation and immutable images.
- Raw output is not persisted, so idempotent replay returns metadata and hashes only. Before
  any raw result enters model context it must pass the later structured redaction boundary.
- No CLI/API/model caller can invoke this service. Authenticated mutation contracts, rate
  limits, event streaming, and public compatibility schemas remain later gates.
