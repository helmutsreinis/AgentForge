## Security and portability review

The profiler reads bounded runtime/native, registry/token, filesystem, proc/sysfs,
distribution, service-marker, and top-level PATH metadata only. It skips Windows UNC
PATH entries, limits directories/files/executables, records truncation, treats raced
or inaccessible entries as gaps, and classifies paths outside known system roots
conservatively. Kali is derived from exact normalized distribution metadata.

The candidate-execution test proves behavior as well as the source boundary: an
otherwise runnable file can be found without its contents being interpreted or its
side effects occurring. Version/help probing and every invocation remain unavailable.
Stored profiles cross structured redaction and are content-addressed; audit output
contains hashes/counts instead of raw paths. CLI path disclosure requires explicit
operator opt-in.

Windows uses registry, token, drive, and filesystem metadata. Linux uses os-release,
proc, sysfs, Unix mode, and service-marker metadata. Unsupported or unavailable
evidence remains typed as unknown/empty without silent execution fallback.
