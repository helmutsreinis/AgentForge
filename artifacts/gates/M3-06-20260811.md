## Security and portability review

Admission accepts no endpoint, credential, secret reference, adapter, or arbitrary policy. It
requires bounded non-sensitive actor/idempotency/correlation metadata, exact correlation with
the model request, current expected installation/agent versions, a context-prepared effective
request hash, and a route plan whose identities and four reservation dimensions match exactly.
Plans with invalid evidence, future use, expiry, or more than a five-second authority lifetime
fail before persistence.

The database uniqueness constraint scopes idempotency to the installation. A fixed-time admission
hash distinguishes exact replay from changed request, authority, attempt history, actor, or
correlation. Run, first attempt, and redacted chained audit event use one commit. A constraint
race clears uncertain tracked state and re-reads the winning record; deterministic concurrency
tests prove one durable result and event.

The schema holds only IDs, versions, typed route/capability/state data, hashes, reservation/usage,
timestamps, and provenance. Prompt/messages, attachment bytes, endpoints, secrets, provider
responses, and remote error bodies have no columns. Pure terminal transitions reject repeated
state changes, overlong plan authority, malformed usage/currency, and normal success/failure after
token, tool, or wall-clock exhaustion. Windows and Ubuntu behavior is identical.

## Remaining findings

- Admission reserves each run against its exact current agent per-request maxima; an atomic
  cross-run ledger and release/reconciliation policy remain required before provider start.
- `Reserved` has no durable start lease, heartbeat, timeout recovery worker, or operational cancel
  service. The pure transitions are not yet exposed.
- Provider/profile authority and destination/DNS evidence must be re-read at start. A persisted
  reservation is not permission to materialize a secret or perform egress.
- Retry attempts beyond the first, health observation updates, cross-attempt usage/cost totals,
  streaming checkpoints, structured-output repair, and no-progress loop detection remain open.
- The production provider and health catalogs remain empty; no public model route exists.
- Docker remains unavailable locally, so the independent live container/namespace gate stays open.

migration note, ledgers, and this report. Keep production catalogs empty and do not attempt to
