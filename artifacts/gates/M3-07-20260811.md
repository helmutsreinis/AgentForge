## Security and portability review

Execution accepts only a reserved run ID/version plus the original request and bounded provenance.
It re-prepares context, repeats current routing with the persisted attempted-profile IDs, compares
route/input/health/reservation evidence, re-reads Ready installation/agent authority, and resolves
only the selected catalog profile. A caller cannot supply a provider object, endpoint, credential,
route, budget, or authority snapshot. Credential-shaped worker/actor/correlation metadata fails
before a lease, ledger row, audit event, or provider call.

One transaction persists `Running`/`Started`, a SHA-256 of a 256-bit random in-memory lease token,
the exact shared reservation, and redacted audit before enumeration. Terminal state requires the
exact token in fixed time and must be within lease expiry. Concurrent starts or ledger updates use
numeric optimistic concurrency and roll back atomically. Active reservations pin the agent version;
an idle ledger may roll forward without discarding cumulative consumption.

Provider events require exact identity/profile/model/prepared-input, contiguous sequence, monotonic
lease-bounded time, bounded text/JSON/error shapes, at most one usage record, and one terminal event.
Tool events are denied. The one overflow event above the maximum reservation remains valid hashed
budget evidence. Canonical event bytes are transient; SQLite and audit store hashes/counts, normalized
usage, and safe classifications only. Fixtures byte-scan for representative raw prompt/output text.

Windows and Linux share the same state machines, repositories, and tests. Migration 0010 gives prior
runs deterministic empty evidence rather than inventing execution. The generated down migration is
destructive and is not an operational rollback.

## Remaining findings

- A crash after committed start leaves `Running` plus an active ledger reservation. There is no
  heartbeat, expired-lease takeover, reconciliation worker, or operator recovery command yet.
- The ledger accumulates token/tool/event/time consumption, but cross-attempt cost/currency totals
  and run-ID membership are protected by the atomic run-version transaction rather than separate
  per-reservation rows.
- Only the first attempt exists. Retryable failures do not yet write durable health observations,
  expand attempt history, create another attempt, or perform bounded failover.
- Hosted profile construction binds exact HTTPS configuration, but destination DNS/IP rebinding and
  production catalog composition remain open. The default catalog is empty.
- Stream content is transiently visible to an explicitly supplied in-process observer; authenticated
  SSE, backpressure receipts, and durable checkpoints remain future gates.
- Docker remains unavailable locally, so the independent live container/namespace gate stays open.
