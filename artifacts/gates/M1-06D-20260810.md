## Security and portability review

Restore is available only after authenticated recovery resumes into `Configuring`.
The application authenticates before snapshot/version disclosure, verifies the full
audit chain and a matching export/recovery event, hashes the bounded artifact itself,
and rejects a document that changes installation, administrator, provider, or agent
topology. Historical declared capabilities are never trusted: current provider
validation materializes the referenced secret and current agent evaluation applies
all bootstrap locality, budget, child, network, and learning bounds.

The preview hash binds the active installation version, immutable snapshot ID/hash,
actor, correlation, every current entity version, and every normalized effective
profile hash. Apply repeats all work. Diff output contains configuration hashes rather
than secret references or raw profile bodies. Restore cannot create identities,
increase topology, recover administrator verifiers, or start runtime activity.

The deterministic restore passes on Windows and Ubuntu. Windows additionally proves
current-user DPAPI after an exact cold copy; copying to another OS identity is
intentionally unsupported. Linux live Secret Service remains credential-gated and
typed unavailable without a session.
