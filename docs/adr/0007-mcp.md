# ADR 0007: Official MCP C# SDK over stdio and Streamable HTTP

Status: Accepted

Use stdio for per-client local processes and Streamable HTTP for network clients.
Legacy SSE is compatibility-only. AgentForge policy filters tools/resources before
advertisement and before invocation. MCP session state never replaces AgentForge
task state, authorization, audit, or idempotency.

The R1 implementation uses the stable official C# SDK 2.0. Streamable HTTP is stateless and protected by the
local-administrator bearer verifier, exact-origin CORS, remote binding validation, and rate limits. Local clients
can launch `agentforge mcp stdio --data-directory <path>`; setup must already be Ready and all logs go to stderr.
Both server transports share an exact configured allowlist and re-check it during invocation. The first enabled tool
and resource return only bounded installation readiness metadata. Client profiles use the same harness-owned policy
shape over official SDK transports: exact allowlists, bounded results, absolute link-free stdio authority, and
loopback/public-HTTPS network scopes. Public HTTP credentials are secret references materialized per request, while a
socket callback rejects mixed or out-of-scope DNS answers. A configured MCP server therefore never becomes ambient
tool, network, process, credential, or context authority.
